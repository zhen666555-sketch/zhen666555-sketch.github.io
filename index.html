我把票券数量、供应商退票和微信退款分开核对，让游客退掉部分门票后，还能拿原票码入园。

22 → 1 每页 20 笔历史订单的回归样例中，读取列表所需的 HTTP 请求次数。

Java 21 / Spring Boot / MySQL

部分退票后，原票码怎么继续用？

申请退 1 张时，先锁定这 1 张，再核对供应商的退票数量和微信退回的金额。核销回调也单独记录。这样一笔 3 张的订单退掉 1 张后，剩余 2 张仍挂在原票码上。

游客小程序和运营后台共用 Spring Boot 交易服务。MyBatis 与 MySQL 保存订单快照、票券镜像、支付尝试和退款记录。

  1. 固定订单快照
  2. 确认支付
  3. 供应商出票
  4. 按张退票

实现细节

  • 服务端确认微信支付，再推进鑫海出票。持久化 outbox、幂等键和人工核对处理超时及重复通知。
  • 部分退款锁定申请中的张数，分别核对核销事件、供应商数量和原支付金额，保留余票及原票码。
  • 历史商品名称、规则及图片从下单快照读取。每页 20 笔订单的回归样例从 22 次 HTTP 请求合并为 1 次批量摘要。

活动改价后，旧报名怎么处理？

修改稿待审期间，原活动照常开放。涉及费用的变更获批后，旧报名保留当时的费用快照，参与者要按新价格重新报名。运营人员可以查到前后两次报名的依据。
